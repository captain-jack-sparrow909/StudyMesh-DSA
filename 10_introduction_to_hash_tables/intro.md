A Hashtable (also known as Hash Map) is a data structure that stores key-value pairs and allows fast lookups, insertions, and deletions. It is an essential tool in programming for efficiently managing and retrieving data.

Hashing, Collisions, Overflow, and Resizing in Hashtables:

The Mailbox Analogy 📬Imagine a post office with 100 numbered mailboxes (0 to 99). Your goal is to store and find files quickly using a person's name.1. Hashing: Finding the BoxA hash function is like a smart postal clerk.You give the clerk a name, like "John".The clerk uses a secret math formula to turn "John" into a number, like 42."John" is always stored in Box 42.This makes finding things instant (O(1) time). You don't search all boxes; you go straight to Box 42.2. Collisions: Two People, One BoxA collision happens when the math formula gives the same box number for two different names.You want to store "Sarah".The clerk runs the math, and it spits out 42 again.Box 42 is already holding John's file.To fix this, computers use two main strategies:Chaining: You put a hook inside Box 42. John's file hangs there. When Sarah arrives, you chain her file right behind John's.Open Addressing: Box 42 is full, so Sarah walks down the line to find the very next empty box (like Box 43) and sits there.3. Overflow: No More RoomIn Chaining: The box never explodes, but the chain gets too long. If 50 names end up in Box 42, the clerk has to search through a long list. It becomes slow.In Open Addressing: If all 100 boxes are filled, there is literally no room left for a new file.4. Resizing and Rehashing: Buying a Bigger CabinetTo fix crowding, the post office buys a new cabinet with 200 boxes instead of 100. This happens when the boxes are about 75% full.But you cannot just move Box 42's files into the new Box 42. Why?The old formula was based on a 100-box grid.The new formula is based on a 200-box grid.Rehashing means the clerk recalculates a new box number for every single file using the new math formula and spreads them out across the 200 new boxes.
